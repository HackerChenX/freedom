## ✏️ 更新进度

### 更新指标状态
```bash
python scripts/update_progress.py <指标名称> <状态> <评分> <完成日期> <问题描述> [备注]
```

### 参数说明

| 参数 | 说明 | 示例 |
|------|------|------|
| 指标名称 | 技术指标的名称 | `MACD`, `RSI`, `KDJ` |
| 状态 | 验证状态 | `PASSED`, `CONDITIONAL_PASS`, `FAILED`, `IN_PROGRESS`, `PENDING` |
| 评分 | 总体评分(0-100) | `95.2`, `80.0` |
| 完成日期 | 验证完成日期 | `2025-08-24` |
| 问题描述 | 主要问题或"无" | `参数管理方法缺失`, `无` |
| 备注 | 可选的额外说明 | `算法一致性100%` |

### 状态类型说明

| 状态 | 图标 | 含义 | 使用场景 |
|------|------|------|----------|
| `PASSED` | ✅ | 完全通过验证 | 所有验证项目都达到优秀标准 |
| `CONDITIONAL_PASS` | ⚠️ | 条件通过 | 核心功能正常，有小问题但可用于生产 |
| `FAILED` | ❌ | 验证失败 | 存在严重问题，需要修复 |
| `IN_PROGRESS` | 🔄 | 正在验证中 | 验证工作正在进行 |
| `PENDING` | ⏸️ | 等待验证 | 尚未开始验证 |

### 更新示例

#### 示例1: 完全通过的指标
```bash
python scripts/update_progress.py RSI PASSED 95.2 2025-08-23 "无" "首个完成验证的指标"
```

#### 示例2: 条件通过的指标
```bash
python scripts/update_progress.py MACD CONDITIONAL_PASS 80.0 2025-08-24 "参数管理方法缺失" "算法一致性100%"
```

#### 示例3: 开始验证的指标
```bash
python scripts/update_progress.py KDJ IN_PROGRESS 0 2025-08-25 "验证中" "开始5阶段验证"
```

#### 示例4: 验证失败的指标
```bash
python scripts/update_progress.py EXAMPLE FAILED 45.0 2025-08-25 "算法错误，计算结果不一致" "需要重新实现"
```

## 🔄 工作流程

### 开始验证新指标
1. **更新状态为进行中**:
   ```bash
   python scripts/update_progress.py KDJ IN_PROGRESS 0 2025-08-25 "验证中" "开始5阶段验证"
   ```

2. **执行5阶段验证**:
   - 算法差异预分析
   - 阶段1: 基础功能验证
   - 阶段2: 形态识别验证
   - 阶段3: 服务层集成验证
   - 阶段4&5: 代码质量与生产就绪验证

3. **完成验证后更新最终状态**:
   ```bash
   python scripts/update_progress.py KDJ PASSED 92.5 2025-08-26 "无" "验证完成，性能优秀"
   ```

### 查看当前进度
```bash
python scripts/view_progress.py
```

### 查看下一个待验证指标
脚本会自动显示按优先级排序的下一批待验证指标。

## 📊 进度表结构

### 指标分类

| 优先级 | 分类 | 数量 | 说明 |
|--------|------|------|------|
| P0 | 核心指标 | 6个 | RSI, MACD, KDJ, BOLL, MA, EMA |
| P1 | 重要指标 | 10个 | DMI, CCI, STOCHRSI等 |
| P2 | 常用指标 | 10个 | ROC, CMO, AROON等 |
| P3 | 专业指标 | 10个 | ENHANCED系列 |
| P4 | ZXM系列 | 10个 | ZXM专有指标 |
| P5 | 系统分析 | 10个 | 评分和分析指标 |

### 验证优先级
按照 P0 → P1 → P2 → P3 → P4 → P5 的顺序进行验证。

## 🚨 注意事项

### 使用脚本前
1. 确保在项目根目录执行脚本
2. 确保 `docs/技术指标验证进度表.md` 文件存在
3. 检查Python环境是否正常

### 更新进度时
1. 指标名称必须与进度表中的名称完全一致
2. 状态必须是预定义的5种状态之一
3. 评分必须是0-100之间的数字
4. 日期格式必须是 YYYY-MM-DD

### 备份恢复
如果需要恢复备份，可以从 `docs/backups/` 目录中选择合适的备份文件覆盖主进度表文件。

## 🎯 最佳实践

### 验证完成后立即更新
每完成一个指标的验证，立即更新进度表，确保信息的及时性。

在问题描述中详细记录发现的主要问题，便于后续改进。

### 定期查看进度
使用 `view_progress.py` 定期查看总体进度，了解项目状态。

### 按优先级验证
严格按照 P0 → P1 → P2 → P3 → P4 → P5 的优先级顺序进行验证。
