- **架构合规**: 严格遵循六层架构，消除跨层调用

- **数据覆盖率**: 50% → 100%

## 🚨 强制执行原则

### 原则1: 数据库强依赖原则
**必须要依赖数据库，如果数据库不可用，就要修复数据层的问题，不可以有兜底逻辑**

### 原则2: 禁止硬编码原则
**要明确禁止硬编码，禁止只测试结果核心指标**

### 原则3: 全局架构视角原则
**每个问题都要从全局架构视角，给出解决方案**

## 🏗️ 分层修复顺序

### 严格的依赖顺序
```
L1基础设施层 → L2存储访问层 → L3数据服务层 → L4核心服务层 → L5业务应用层 → L6用户接口层
```

### 修复原则
1. **从最底层开始**: 严格按依赖顺序修复
2. **单一入口原则**: 每个功能只能有一个标准入口
3. **现有功能整合**: 在现有功能基础上优化整合
4. **标准化要求**: 建立统一标准，严禁混乱不清

## 🧪 分层测试标准（新增强制要求）

### 测试原则
**每修复一层，就测试一层。测试完全通过，日志没有任何报错才能进入下一任务**

### 测试要求
1. **功能测试**: 该层所有功能必须正常工作
2. **集成测试**: 与已修复层的集成必须正常
3. **性能测试**: 必须满足性能要求
4. **日志检查**: 日志中不能有任何ERROR或WARNING
5. **标准验证**: 必须符合标准化要求

### 阻断机制
- ❌ **测试不通过**: 禁止进入下一层修复
- ❌ **日志有报错**: 必须解决所有错误
- ❌ **性能不达标**: 必须优化到达标
- ❌ **标准不符合**: 必须重构到符合标准
