# 数据库层修复执行计划

## 🎯 执行目标

基于深度分析结果，按照"修复现有系统，不创建新入口"的原则，系统性解决数据库连接和服务注册问题。

## 📋 执行阶段

### 阶段1: 容器统一修复（立即执行）

#### 任务1.1: 清理污染的容器方法
**目标文件**: `db/container.py`
**问题**: 方法名被污染，如`register_singleton_Container`
**修复方案**: 
1. 重命名所有污染的方法名
2. 移除重复的容器实现
3. 统一使用`utils/unified_container.py`

#### 任务1.2: 修复字符串键注册
**问题**: 使用字符串键导致重复注册
**修复方案**:
```python
# 当前错误方式
container.register_singleton_by_name('STOCK_LIST', factory)

# 修复后方式  
from typing import List
container.register_singleton(List[str], factory)
```

#### 任务1.3: 移除重复的服务注册
**位置**: 
- `db/service_registry.py:42`
- `config/container_config.py:55`
- `db/container.py:271-292`

**修复方案**: 创建统一的服务注册入口，确保每个服务只注册一次

### 阶段2: 连接池单例化（高优先级）

#### 任务2.1: 保留唯一连接池入口
**保留**: `db/enhanced_connection_pool.py:get_connection_pool()`
**移除重复创建点**:
1. `db/managers/connection_manager.py:148` - _initialize_pool_Connection_Manager()
2. `db/data_manager_adapter.py:59` - initialize_connection_pool()调用
3. `db/unified_data_manager.py:76` - 另一个initialize_connection_pool()调用
4. `monitoring/clickhouse_performance_monitor.py:147` - 监控模块初始化
5. `api/main.py:118` - API启动时直接创建

#### 任务2.2: 修复连接池依赖注入
**当前问题**: 多个地方直接创建连接池实例
**修复方案**: 所有地方都通过依赖注入获取连接池

```python
# 错误方式（需要修复）
pool = ClickHouseConnectionPool()

# 正确方式（目标）
pool = container.resolve(ClickHouseConnectionPool)
# 或者
pool = get_connection_pool()  # 全局单例函数
```

### 阶段3: 架构边界清理（中优先级）

#### 任务3.1: L2层职责清理
**文件**: `db/enhanced_connection_pool.py`
**当前问题**: 包含过多业务逻辑
**修复方案**: 
- 保留：连接管理、查询执行、健康检查
- 移除：业务逻辑、数据聚合、缓存管理

#### 任务3.2: L3层职责明确
**文件**: `db/managers/data_access_manager.py`
**当前问题**: 直接创建连接池，违反依赖注入
**修复方案**:
- 通过构造函数注入连接池
- 添加数据聚合功能
- 实现缓存管理

### 阶段4: 语法错误修复（中优先级）

#### 任务4.1: 修复ZXM指标语法错误
**文件**: `indicators/zxm/zxm_abstract_methods_mixin.py:120`
**问题**: 变量赋值语法错误
**修复**: 已部分修复，需要完成剩余错误

#### 任务4.2: 修复成交量指标语法错误
