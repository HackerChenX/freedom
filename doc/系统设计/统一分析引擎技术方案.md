# 统一分析引擎技术方案

## 1. 方案概述

### 1.1 背景问题
- 买点分析和策略选股使用不同的计算引擎，导致结果不一致
- 策略选股不支持复杂的复合逻辑，功能受限
- 两个系统的底层逻辑重复开发，维护成本高
- 策略选股缺乏智能的日期处理机制

### 1.2 方案目标
1. **统一计算引擎** - 共享技术指标计算逻辑
2. **支持复杂逻辑** - 策略选股支持买点分析的所有逻辑类型
3. **智能日期处理** - 自动使用最新可用数据进行分析
4. **提升性能** - 通过统一引擎减少重复计算
5. **简化维护** - 单一代码路径，降低维护复杂度

### 2.2 核心组件设计

#### 2.2.1 统一指标计算引擎 (UnifiedIndicatorEngine)

**职责**：
- 统一所有技术指标的计算逻辑
- 提供标准化的指标计算接口
- 支持多周期数据处理
- 内置缓存机制提升性能

**核心方法**：
```python
class UnifiedIndicatorEngine:
    def calculate_ma(self, data: pd.DataFrame, period: int) -> pd.Series
    def calculate_macd(self, data: pd.DataFrame, fast: int, slow: int, signal: int) -> Dict
    def calculate_kdj(self, data: pd.DataFrame, k_period: int, k_smooth: int, d_smooth: int) -> Dict
    def calculate_rsi(self, data: pd.DataFrame, period: int) -> pd.Series
    def calculate_all_indicators(self, data: pd.DataFrame) -> Dict[str, Any]
```

#### 2.2.2 共享条件评估器 (SharedConditionEvaluator)

**职责**：
- 统一条件评估逻辑
- 支持简单条件和复杂条件
- 提供条件组合能力
- 支持自定义条件扩展

**支持的条件类型**：
```python
# 基础条件
{
    "type": "basic",
    "field": "close",
    "operator": ">",
    "value": 10
}

# 指标条件
{
    "type": "indicator",
    "indicator": "MA",
    "period": 5,
    "field": "MA5",
    "operator": ">",
    "reference_field": "close"
}

# 形态条件
{
    "type": "pattern",
    "pattern": "touch_ma",
    "params": {"tolerance": 0.01}
}

# 复合条件
{
    "type": "composite",
    "logic": "and",
    "conditions": [...]
}

# 复杂逻辑条件
{
    "type": "complex",
    "logic_expression": "touch_ma AND price_stable AND (ma_up OR money_in)"
}
```

#### 2.2.3 复杂逻辑处理器 (ComplexLogicProcessor)

**职责**：
- 处理买点分析中的复杂逻辑
- 支持形态识别
- 支持多维度综合判断
- 提供逻辑表达式解析

**核心功能**：
```python
class ComplexLogicProcessor:
    def evaluate_touch_ma(self, data: pd.DataFrame, date_idx: int) -> bool
    def evaluate_price_stable(self, data: pd.DataFrame, date_idx: int) -> bool
    def evaluate_ma_up(self, data: pd.DataFrame, date_idx: int) -> bool
    def evaluate_money_in(self, data: pd.DataFrame, date_idx: int) -> bool
    def evaluate_complex_expression(self, expression: str, data: pd.DataFrame, date_idx: int) -> bool
```

#### 2.2.4 日期管理器 (DateManager)

**职责**：
- 智能日期处理
- 自动获取最新可用数据日期
- 处理交易日历
- 支持相对日期计算

**核心方法**：
```python
class DateManager:
    def get_latest_trading_date(self, stock_code: str) -> str
    def get_trading_date_before(self, date: str, days: int) -> str
    def is_trading_day(self, date: str) -> bool
    def get_data_date_range(self, end_date: str, periods: int) -> Tuple[str, str]
```

## 4. 技术细节

### 4.1 数据流设计

```
输入数据 → 数据预处理 → 指标计算 → 条件评估 → 结果输出
   ↓            ↓           ↓          ↓          ↓
股票代码      标准化格式    统一引擎    共享评估器   标准结果
日期范围      缓存检查      批量计算    复杂逻辑    性能统计
```

### 4.2 缓存策略

**指标计算缓存**：
- 缓存键：`{stock_code}_{period}_{start_date}_{end_date}_{indicator_params}`
- 缓存时效：1小时（盘中），24小时（收盘后）
- 缓存容量：1000个条目

**条件评估缓存**：
- 缓存键：`{condition_hash}_{stock_code}_{date}`
- 缓存时效：30分钟
- 缓存容量：5000个条目

### 4.3 性能优化

**并行计算**：
- 股票级别并行：多个股票同时处理
- 指标级别并行：多个指标同时计算
- 条件级别并行：多个条件同时评估

**内存优化**：
- 数据分块处理：大数据集分块加载
- 及时释放：不需要的数据及时释放
- 对象池：重用计算对象

### 4.4 扩展性设计

**插件化架构**：
- 指标插件：支持自定义指标
- 条件插件：支持自定义条件
- 逻辑插件：支持自定义逻辑

**配置化驱动**：
- 指标配置：参数可配置
- 条件配置：逻辑可配置
- 策略配置：策略可配置

## 5. 风险控制

### 5.1 兼容性风险

**风险**：重构可能破坏现有功能
**控制措施**：
- 保持现有接口不变
- 创建适配器层
- 全面的回归测试

### 5.2 性能风险

**风险**：统一引擎可能影响性能
**控制措施**：
- 性能基准测试
- 分阶段优化
- 监控关键指标

### 5.3 数据一致性风险

**风险**：不同引擎可能产生不同结果
**控制措施**：
- 严格的单元测试
- 对比验证测试
- 数据校验机制
